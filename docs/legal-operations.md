# Документы некоммерческого запуска

Полные пользовательские тексты поставляются с frontend в `src/features/legal/documents.js` и отображаются в `/legal/privacy`, `/legal/terms`, `/legal/consent`, `/legal/cookies`, `/legal/offer`. Последний адрес описывает рекламный модуль и прямо сообщает, что платная публичная оферта отсутствует. Покупка услуг, платная подписка и платежи не реализованы.

Тексты описывают фактические OAuth permissions, профиль, социальные данные, localStorage/sessionStorage, сторонний Twitch player, модерацию и отсутствие автоматического удаления аккаунта. Они не обещают несуществующую автоматизацию исполнения юридических обязанностей. По указанию владельца поля оператора и email оставлены для заполнения. Наличие этих текстов позволяет технически пользоваться OAuth с настроенными Twitch credentials; оно не подтверждает соответствие требованиям конкретной страны.

Перед открытием сервиса публике заполните `LEGAL_OPERATOR_NAME`, `LEGAL_CONTACT_EMAIL`, при необходимости `LEGAL_ADDRESS`. Установите применимую юрисдикцию, сроки удаления данных и резервных копий, процедуру обращений и необходимые основания обработки. Некоммерческий статус сам по себе не отменяет обязанностей при обработке данных. Удаление по обращению сейчас требует контролируемой работы оператора с базой и зависимыми данными; не выдавайте выход или отзыв Twitch за удаление аккаунта.

Для собственной опубликованной редакции задайте абсолютные HTTPS `LEGAL_PRIVACY_URL`, `LEGAL_TERMS_URL`, `LEGAL_CONSENT_URL`, `LEGAL_COOKIES_URL`, `LEGAL_OFFER_URL`; пустое значение использует встроенный текст. Внешняя редакция открывается по ссылке, произвольный HTML не вставляется. Не направляйте override на эту же страницу `/legal/*`: это создаст бесполезный переход на себя.

При изменении документов меняйте `LEGAL_CONSENT_VERSION` одновременно для всех API/worker. Сервер записывает принятую версию и серверное время при OAuth; окно входа требует отдельного подтверждения. Изменение версии не является механизмом мгновенного отзыва всех уже существующих JWT — для этого предусмотрен auth_version.

Рекламные кампании по умолчанию отсутствуют. До их включения настройте точный HTTPS allowlist `ADS_MEDIA_HOSTS`, права на материалы, данные рекламодателя и маркировку. Биллинг, регистрация рекламы и юридическая проверка не выполняются приложением. UI отделяет рекламу от клипов; счётчики основаны на подтверждениях браузера и не являются антифродом.
