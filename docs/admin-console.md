# Консоль управления

`/admin` доступен администраторам, `/staff` — модераторам и администраторам.
Обе консоли используют общие разделы пользователей, жалоб, сетевых блокировок,
журнала и диагностики. Статистика платформы, импорт, реклама и продвижение
доступны в административной консоли.
Ссылка «Консоль» ведёт администратора в `/admin`, модератора — в `/staff`.
При открытии `/staff` администратор также получает полный набор разделов.

## Пользователи и доступ

Найдите аккаунт по имени, выберите «Управлять». В карточке показаны фактическая
роль, доступ к аккаунту, ограничения обсуждений, сроки и причины. Вводить ID
для блокировки или отстранения не требуется. Администратор также может искать
по почте и менять роль в этой карточке. Модератору почта не передаётся.
Ссылки «Управлять доступом» в профиле и «Доступ автора» в комментариях открывают
эту же карточку напрямую и отображаются только персоналу.

Доступны фильтры: активные, заблокированные, отстранённые и с ограниченными
обсуждениями. «Активные» означает наличие доступа к аккаунту; ограничения
обсуждений учитываются отдельно. Поиск выполняется после отправки формы,
фильтры применяются на сервере, пагинация — по 30 записей. Символы `%` и `_`
в поиске рассматриваются буквально.

Изменение доступа требует причины и отдельного подтверждения с именем
пользователя. Для временных ограничений срок составляет 1–8760 часов.
Бессрочное ограничение обсуждений не отправляет скрытый временный срок.
При ошибке решение остаётся открытым для повторной отправки или исправления.
Возврат через «Назад» сохраняет введённые причину и срок и возвращает фокус
на кнопку продолжения. Для заблокированного или отстранённого аккаунта
по умолчанию предлагается восстановление доступа. Пока запрос выполняется,
повторная отправка и закрытие карточки недоступны.

Для модератора карточка сотрудника с равной или более высокой ролью доступна
только для чтения: интерфейс не предлагает действия, запрещённые сервером.
Поиск пользователей использует общий [SearchField](shared-ui.md); кнопка
очистки сбрасывает также применённый поисковый запрос.

Сервер сохраняет существующие гарантии: нельзя ограничить себя, модератор
не может ограничить сотрудника с равными или более высокими правами, нельзя
ограничить последнего активного администратора. Изменения ролей и аккаунтные
блокировки продолжают отзывать сессии согласно существующему контракту.

## Жалобы и журнал

Жалоба привязана к `target_type` и `target_id`. Для клипа доступны переход к
клипу, управление видимостью и классификацией. Для комментария — текст,
переход к обсуждению, карточка автора и удаление. Для пользователя открывается
карточка доступа. Решение по жалобе (`dismissed` / `actioned`) выполняется
отдельно от изменения контента: скрытие клипа само по себе не закрывает жалобу.

Журнал показывает имена исполнителя и целевого пользователя; ссылка на
пользователя открывает его карточку. Если аккаунт удалён, остаётся ID.
Удаление чужого комментария персоналом записывается в журнал в той же
транзакции, что и удаление; обоснование можно передать через JSON `reason`
в `DELETE /comments/:id`. Вызовы без тела сохраняют прежнее поведение.

Блокировки IP остаются отдельным сетевым инструментом: общий IP может
принадлежать нескольким аккаунтам. Создание блокировки требует подтверждения.

## Статистика и графики

Recharts загружается вместе с отложенно загружаемой консолью. Диаграммы
показывают текущий состав сообщества, категории каталога, почасовое добавление
клипов за последние 24 часа и суммарные счётчики рекламы. Оси времени и
подсказки импорта используют часовой пояс браузера. Точные значения доступны
в раскрываемых таблицах. Отсутствие телеметрии не заменяется фиктивной историей.

Графики и таблицы не анимируют поступление данных. Диалоги и Select используют
общую систему motion: прерываемые переходы, существующие кривые и длительности,
мгновенная работа при клавиатурном вводе и reduced motion. Навигация учитывает
`prefers-reduced-transparency` и `prefers-contrast`. Подход основан на
`emil-design-eng`, `animate`, `apple-design` и `mobile-native` из
[emilkowalski/skills](https://github.com/emilkowalski/skills).

## API каталога персонала

`GET /moderation/users?q=<поиск>&status=<фильтр>&limit=30&offset=0`

- Только активный модератор или администратор.
- `status`: пустое значение, `active`, `blocked`, `suspended`, `chat`.
- `limit`: 1–100; `q`: до 256 байт UTF-8.
- Ответ: `users`, `total`, `has_more`; почта присутствует только у администратора.
- Подробности: существующий `GET /moderation/users/:id`.
- Действия: существующий `POST /moderation/users/:id/restriction`.

Миграции базы данных для переработки консоли не требуются.
